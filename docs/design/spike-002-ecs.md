## 2. 结果

| # | ADR-001 §5 的判据 | 结果 |
|---|---|---|
| 1 | 三种组件：数值 / 字符串 / 对象引用 | **通过** |
| 2 | 运行时注册一个模块的组件集 | **通过** |
| 3 | 快照 → 改 100 个实体 → 回滚 | **通过**（自写，约 6 行——ADR §4.2 估的"几十行"偏保守） |
| 4 | 10k 实体查询循环 | **1.11 ms/帧**（预算 16.6 ms，余量 15 倍） |
| **5** | **确定性：迭代顺序** | **见下** |
| 6 | 书写体验 | `world.query(P, V).updateEach(([p, v]) => p.x += v.x)` |

### 2.1 第 5 条（杀手判据）分两档测

**温和档**——只增删组件、且对称恢复：

| 场景 | 结果 |
|---|---|
| 同一逻辑终态、两条不同操作历史 | 顺序**一致** |
| 增删组件后再恢复 | 顺序**一致** |
| 顺序恰为 spawn 顺序 | **是** |

**这一档全过，但它太温和，不足以下结论。**
原型式 ECS 真正会露馅的地方是**实体销毁后 id 被复用**，以及**同一查询命中多个不同原型**。
（Rapier spike 的教训：不植入负例，"通过"可能只是测试没在测东西。）

**严格档**——销毁一半实体 + 补建新实体触发 id 复用 + 1/3 实体多带一个 Tag 形成混合原型：

| 场景 | 结果 |
|---|---|
| 同一操作序列重放两次 | 顺序**一致** ✅ |
| 顺序是否天然升序 | **否** ⚠️ |

### 2.2 怎么读这个结果

两个结论，必须分开看：

> **① 重放确定性成立。** 同一操作序列跑两次，迭代顺序完全一致。
> **这是决策 29 的底线，koota 守住了。**
>
> **② 但顺序不是稳定 id 升序。** id 复用后，复用出来的实体排在了它 id 应有位置之外。

**② 不是失败**，它正是 [ADR-001 §6](adr-001-ecs.md#6-退役条件按-goalsmd-72-预先写死) 预写的升级路径第 ① 步所针对的情形：

```
库自身不能保证稳定的查询迭代顺序
  → ① 封装层统一按稳定实体 id 排序后再交给系统   ← 落在这里
```

§6 原文说"① 应该覆盖绝大多数情况"——**实测确认了这个判断**。

**因此这条不是选型问题，是封装层的一项必需职责**：
`query()` 必须在交给系统之前按稳定 id 升序排序。
这同时也是 [ADR-002 §8 的 D1](adr-002-eventsheet-eval.md#8-确定性的四条附加约束)
（"实体迭代顺序按稳定 id 升序，不按 ECS 原型的内存顺序"）的执行点——
**两份 ADR 在这里对上了，且是实测对上的，不是纸面推的。**

## 3. bitECS 对照

只做了**局部**对照（顺序 + 书写体验），**没有跑完整六条**——
理由是 ADR-001 §4.2 的权重是 **ISC 许可证 > 书写体验 > 活跃度**，
koota 六条全过时，bitECS 的完整 spike 不影响结论。**这是本轮的一处范围限制，写出来。**

| | koota | bitECS |
|---|---|---|
| 同终态 / 不同历史顺序一致 | 通过 | 通过 |
| 书写体验 | `p.x += v.x` | `Position.x[eid] = 10`——**eid 写错会静默改到别的实体** |
| 许可证 | **ISC** | **MPL-2.0**（文件级弱著佐权，改动过的源文件须公开） |

若日后 koota 出问题，bitECS 仍是候选，但要先算 MPL-2.0 那笔账
（本项目几乎一定会改 ECS 源码：快照要接版本化信封、确定性要审计迭代顺序）。

## 4. 对 ADR-001 与下游的影响

1. **ADR-001 转「已验证」**，`4.2 主选 koota` 锁定。
2. **封装层新增一项硬职责**：`query()` 按稳定 id 升序排序。
   这不是优化，是 [决策 29](goals.md#二--决策表) 与 [ADR-002 D1](adr-002-eventsheet-eval.md) 的执行点，
   **M1-a 必须带着它落地**，不能等到发现回放对不上再补。
3. **`U-001` 关闭**（ECS 库选型）。
4. **`U-002` 不变**（组件 schema 定义方式）——spike 反而确认了 ADR §3 的"发现 1"：
   koota 的 `trait({x:0})` 只能推出类型，推不出范围、枚举、实体引用、单位、说明。
   **详情面板自动生成与 AI 可读所需的 schema，封装层无论如何要自己写。**

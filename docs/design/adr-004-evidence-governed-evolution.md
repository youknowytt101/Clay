## 1. 问题

Clay 的所有者不可能预先知道每个关键技术问题，也不应该靠自己逐行识别 AI 的错误与漂移。
已有的文档治理能发现版本、链接和部分事实漂移，[ADR-003](adr-003-verified-agent-loop.md) 能约束 AI 怎样执行，
但两者都没有回答：

1. 谁负责发现**用户没有提出的隐含决策**；
2. 如何区分事实、假设、偏好和暂定方案；
3. 当前最优解在什么证据下可以被替换；
4. 发现不了错误的所有者，如何在不充当技术 oracle 的情况下保留最终控制；
5. 这套发现机制本身如何改进，而不演变成 AI 静默修改自己的约束。

本 ADR 建立的是**项目研发治理协议**。它约束接手仓库、设计和实现 Clay 的 AI，也为未来产品内的设计代理提供上游规则；
它不把运行期游戏 AI 纳入范围。

---

## 2. 决策摘要

> **Clay 采用证据治理的滚动开发：意图与权限受保护，方案与机制可挑战；每个非平凡任务先扫描决策面，
> 暴露假设与未知项，再通过独立质疑、可逆实验、可重放证据和 champion/challenger 比较推进。**

八条硬规则：

1. **用户不承担“找出所有错误”的责任。** 执行 AI 必须主动枚举隐含决策、空白和反例。
2. **事实、假设、偏好、约束和决策分开记录。** 未经证据支持的内容不得冒充事实。
3. **决策面不许留白。** 每个维度只能是已覆盖、不适用（有理由）、未决（有登记）或由上游覆盖（有链接）。
4. **高风险未知只阻塞依赖它的不可逆提交，不阻塞无关工作。** 可逆工作通过适配层、候选分支、feature flag 或 shadow mode 继续。
5. **AI 可以挑战任何当前方案，但不能静默改写。** 不变量、产品意图、hard oracle、权限和历史只能由项目所有者批准变更。
6. **独立质疑不是投票。** 结论由可重放证据与反例裁决，不由模型数量或措辞可信度裁决。
7. **当前最优解只是有版本的 champion。** challenger 必须在同一硬判据下不退化，并证明收益、迁移和回退，才能取代。
8. **治理机制也用同一协议演化。** 新检查表或新流程先影子运行，通过历史漏判集与新植入反例后才能成为 champion。

## 3. 权限内核：什么能进化，什么不能自动改变

| 层 | 内容 | AI 权限 | 采用权限 |
|---|---|---|---|
| **L0 意图内核** | 一句话定义、不变量、目标水位、项目所有者保留权 | 可提出 `DecisionChallenge`，不可直接修改 | **仅项目所有者** |
| **L1 裁决** | 决策表、ADR 结论、hard gate、冻结语义 | 可调研、提出候选和补丁，不可宣布生效 | **项目所有者批准 + 留痕** |
| **L2 计划** | 路线、任务契约、风险路由、实验顺序 | 可持续优化；越过已批准 scope 时必须挑战 | 低风险可按已批准契约执行，结构改动需批准 |
| **L3 实现** | 代码、测试、提示词、适配器、检查脚本 | 可在事务、测试和权限内迭代 | 按 [ADR-003](adr-003-verified-agent-loop.md) 或仓库工作流提交 |
| **L4 证据** | 观测、轨迹、基准结果、失败样本 | 只增不改；纠错追加新记录 | 引擎/工具生成，人和 AI 都不能改旧结果 |

“AI 可以不断优化”指 L2–L3 可以按证据循环演化，L0–L1 可以被挑战但不能被绕过。
任何声称“为了优化流程所以顺便改了目标或验收”的行为都属于越权。

## 4. 五种结构化材料

### 4.1 `TaskContract`

每个非平凡任务在计划或实现前必须具备：

```ts
type TaskContract = {
  objective: string;
  authority: string[];
  protectedIntent: string[];
  knownFacts: EvidenceRef[];
  assumptions: Assumption[];
  scope: string[];
  outOfScope: string[];
  decisionCoverage: DecisionCoverage;
  acceptance: EvidenceRequirement[];
  stopConditions: string[];
};
```

任务很小时可以是一段结构化 Markdown，不要求先建设数据库。`authority` 说明谁能决定什么，
`protectedIntent` 防止 AI 把技术便利误写成产品方向，`assumptions` 必须带失效条件。

### 4.2 `DecisionCoverage`

```ts
type CoverageCell = {
  dimension: string;
  status: 'covered' | 'not-applicable' | 'open' | 'inherited';
  refs: string[];
  rationale?: string;
};
```

空字符串不是一种状态。`open` 必须指向 §9 的 `U-NNN`；`inherited` 必须指向决策、ADR 或不变量；
`not-applicable` 必须说明为什么。覆盖表描述“检查过什么”，不声称“没有未知的未知”。

### 4.3 `UncertaintyItem`

```ts
type UncertaintyItem = {
  id: `U-${string}`;
  statement: string;
  type: 'fact' | 'semantic' | 'architecture' | 'product' | 'delivery';
  irreversibility: 1 | 2 | 3;
  uncertainty: 1 | 2 | 3;
  blastRadius: 1 | 2 | 3;
  deadline: string;
  evidenceRequired: string;
  status: 'open' | 'testing' | 'resolved' | 'superseded';
};
```

风险分数为 `irreversibility × uncertainty × blastRadius`，它只用于路由，不伪装成精确概率。
登记表的单一真源是 [goals.md §9](goals.md#九--未决项)。解决后不删行，转入“已决并移出”并链接证据。

### 4.4 `DecisionChallenge`

```ts
type DecisionChallenge = {
  challengedRef: string;
  trigger: string;
  hiddenDecision: string;
  options: Option[];
  currentEvidence: EvidenceRef[];
  recommendation: string;
  reversibleProbe: string;
  workThatMayContinue: string[];
  authorityNeeded: string;
};
```

挑战不是一句“这里可能有问题”。它必须说明不决定的代价、最小验证方式，以及哪些无关工作仍能继续。
挑战可以针对用户、历史决策、其他 AI 或本协议本身。

### 4.5 `EvidenceRecord` 与 `EvolutionProposal`

`EvidenceRecord` 至少记录：被验证的断言、环境与版本、输入、方法、原始输出引用、判定规则、结果、限制、复现方式和作者/模型。
自然语言总结不是原始证据，市场事实必须有来源和复查日期。

`EvolutionProposal` 至少记录：champion、challenger、保持不变的 hard criteria、预期收益、反例集、比较结果、
迁移计划、回退条件、影响范围和批准者。没有 champion 基线或没有回退的“优化”不能进入正式路径。

## 5. 强制决策面

每个新能力、接口、schema、状态机或跨模块行为至少扫描下列十二面：

| # | 决策面 | 必答问题 |
|---|---|---|
| D1 | 输入 / 输出 | 输入是否合法、输出由谁消费、空值和部分结果是什么 |
| D2 | 身份 / 关联 | 对象如何寻址、多个对象如何配对、引用何时失效 |
| D3 | 状态 / 生命周期 | 创建、可见、修改、销毁、恢复各发生在何时 |
| D4 | 顺序 / 并发 | 稳定顺序是什么、同 tick 或并发冲突怎样裁决 |
| D5 | 时间 / 随机 / 精度 | tick 舍入、随机源、数值类型、平台差异怎样处理 |
| D6 | 失败 / 中断 / 重试 | 失败是否污染状态、何时停止、是否幂等 |
| D7 | 撤销 / 迁移 / 兼容 | 能否回退、旧数据怎样打开、冻结边界在哪里 |
| D8 | 权限 / 安全 / 副作用 | 谁能读写什么、外部内容是否可信、哪些副作用禁止 |
| D9 | 可观察 / 可验证 | hard oracle 是什么、怎样复现、怎样植入负例 |
| D10 | 性能 / 规模 / 退化 | 上限怎样测、超限时换实现还是改语义 |
| D11 | 契约 / 依赖 | 上下游是谁、变化如何传播、适配边界在哪里 |
| D12 | 用户控制 / 修复 | 用户看到什么、能否接手、错误恢复距离是多少 |

此外必须做一次**负空间扫描**：非法输入、空集合、重复请求、乱序、并发修改、部分失败、版本不一致、
极值、跨平台、权限不足、旧数据和恶意内容。领域 ADR 可以增加专用维度，但不能删除这十二面。

当任务涉及**规则、表达式或状态机**时，还必须在 D1–D2 下启用条件式逻辑探针：

1. AND / OR / NOT 的真值、作用域和集合组合；
2. `any` / `all` / `none` 的量词边界，尤其空集合；
3. 短路是否发生，以及 RNG、事件、计数器等副作用是否被消费；
4. 运算符优先级是否固定，或是否强制括号；
5. 各分支看到的实体集、绑定如何传播、合并和去重。

这不是普适 D13。纯编辑、继承既有契约的测试和行为保持重命名等任务只需说明不适用；
探针不得靠给所有任务发挑战来换取召回率。

## 6. 风险路由与停止条件

| 分数 | 路由 | 允许的推进方式 |
|---|---|---|
| **18–27 关键** | 先挑战与验证，相关语义不得提交 | 纸面推演、spike、双实现对拍、候选分支、外部专家审查 |
| **8–17 受控** | 先写适配与回退，再实现 | feature flag、版本字段、可替换接口、shadow mode |
| **1–7 可逆** | 采用当前最佳假设推进 | 记录假设、触发条件和回退点；证据出现时可重开 |

下列信号不看分数，立即发出 `DecisionChallenge`：

- 权威文档冲突，或同一需求存在两种合理且结果不同的语义；
- 新增不可逆 schema、协议、标识符、求值顺序或外部副作用；
- 需要改变不变量、hard oracle、scope、权限或已批准验收；
- 任务依赖未登记的假设，或现有证据反驳 champion；
- 新增只有一个目标游戏使用的内核原语；
- 验收无法判定、失败无法重放，或 reviewer 与 builder 共用未经隔离的自我结论；
- 连续失败表明缺的是决策或原语，而不只是实现错误。

发出挑战后，只有相关不可逆提交暂停；`workThatMayContinue` 中的工作照常推进。

## 7. 独立质疑与证据强度

独立性按风险增加，不强制多 agent，也不把多数票当真理：

| 风险 | 最低质疑方式 |
|---|---|
| 可逆 | 执行者自己做决策面和负空间扫描，测试反驳自身结论 |
| 受控 | 隔离上下文的 skeptic 只读目标、候选方案和证据，不接收 builder 的“已经正确”结论 |
| 关键 | 隔离 skeptic + 至少一种异质证据：参考实现、标准/官方来源、第二实现、另一 provider 或领域专家 |

质疑者必须优先寻找：隐含前提、反例、替代解释、不可逆点、评价指标被投机通过的路径。
如果 reviewer 和 builder 给出不同结论，不合并成折中方案；回到证据不足项，设计能区分两者的实验。

## 8. 追踪链与交接证据包

每条实施路径必须可追到：

```text
产品意图 / 不变量
  → 目标场景与失败场景
  → 决策面覆盖
  → 决策 / ADR / U-NNN
  → 计划步骤与实现
  → hard / soft 验收
  → EvidenceRecord
  → 当前判定与剩余未知
```

自动检查至少发现：孤儿目标、无场景的决策、无验收的实现任务、无证据的“已验证”、
无上游引用的测试，以及修改上游后没有更新的下游投影。

每次 AI 交接必须提供同一份 evidence package：已完成、真实改动、测试结果、失败与限制、
新增/关闭的 `U-NNN`、触发的挑战、剩余风险、可复现命令和下一决策截止点。
“已完成”但没有可重放证据的任务，状态只能是“待验证”。

## 9. 方案演化：champion / challenger

当前方案不是永恒真理，而是带版本和证据的 champion。AI 可以随时提出 challenger，但采用必须依次满足：

1. 明确 champion 的适用范围、失败条件与基准证据；
2. challenger 使用**同一组 hard criteria**，不得删测试、换指标或缩小样本来制造胜出；
3. 至少补一个能区分两者的新反例或真实场景；
4. 比较正确性、错误通过、恢复距离、成本、性能和可维护性；只优化一轴时公开其他轴变化；
5. 关键方案先 shadow / candidate 运行，不直接覆盖主路径；
6. 写出数据/接口迁移与一键回退条件；
7. 证据可复现，项目所有者批准 L0–L1 变化；
8. 采用后保留旧结论和证据，ADR 转“已取代”，不改写历史。

新证据若只证明“不同”，不证明“更好”，则两者保持候选，不强行收敛。

## 10. 机制演化：让发现系统优化自己

决策面、风险阈值、检查器、提示模板和交接格式都可以演化，但采用更严格：

1. 建立治理基准集：历史真实漏判 + 人工植入的关键遗漏 + 无问题对照任务；
2. 新机制作为 challenger 在 shadow mode 运行，不影响当前 champion 的裁决；
3. 同时测**关键遗漏召回率**与**无效挑战负担**，不能靠把所有任务都拦下来获得高召回；
4. 植入案例中，关键遗漏必须全部被发现，越权修改必须为 0；
5. 每新增一个必填字段或检查步骤，必须指出它抓住了哪个失败模式；无收益项应删除或降级；
6. 基准集持续加入新逃逸案例，并保留一组由独立上下文生成、执行者事先未针对调优的案例；
7. 机制升级自身也要提交 `EvolutionProposal`，保留旧版本、迁移与回退；
8. AI 可以生成和验证升级提案，但不能自行批准改变 L0–L1 权限边界。

这使机制能学习真实失败，而不是无限增加文档和检查表。**复杂度不是进化指标，漏判更少且审阅负担可控才是。**

## 11. 指标

| 指标 | 定义 |
|---|---|
| **关键决策逃逸率** | 依赖实现开始后才发现的关键决策 / 全部关键决策 |
| **静默假设数** | 任务结束后才暴露、且未进入 `assumptions` 或 `U-NNN` 的假设数 |
| **追踪断链数** | 缺少上游、验收或证据链接的活动项数 |
| **植入遗漏召回率** | 被机制发现的人工植入关键遗漏 / 植入总数 |
| **无效挑战负担** | 最终无新信息、无风险降低的挑战 / 挑战总数，并记录人工处理量 |
| **证据复现率** | 独立环境得到相同 hard 判定的证据记录 / 被抽查记录 |
| **回退距离** | challenger 失败后恢复 champion 所需的非自动步骤与数据损失 |
| **决策重开收益** | 重开后实际减少的失败、成本或不可逆风险；没有收益的重开计为机制负担 |

目标不是追求“挑战越多越好”。首轮冻结只设三条硬线：人工植入的关键遗漏召回率 100%、
越权变更 0、被抽查证据可复现；其余阈值由 M0-d 的真实分布决定，避免纸面编造。

## 12. 三个回放样例与冻结条件

### G1 · 回放 v17 / v19 文档漂移

给执行者互相冲突的目标用户、模板数量和 ADR 状态投影。要求覆盖扫描发现权威冲突、
追踪断链和静默重写风险；不得凭多数文档选择答案。输出一个 `DecisionChallenge` 和仍可继续的纯校验工作。

### G2 · 回放 ADR-002 的隐含语义

给出“两座塔各打最近敌人”，但不提示对象关联、相同距离、销毁可见性、OR、排序和精度问题。
要求 D2–D5、负空间和条件式逻辑探针主动产生 `U-NNN` / 微案例；如果只复述用户给出的三个样例则失败。

### G3 · 让协议挑战自己

准备一组含关键遗漏和无问题对照的任务，让现行机制与一个减少/增加检查步骤的 challenger 影子运行。
要求报告遗漏召回、无效挑战负担、成本和越权尝试，并完整走一次采用或拒绝及回退；
不得因为 challenger 更复杂或来自更新模型就宣布它更优。

### 转状态条件

- G1–G3 由隔离上下文回放，人工植入的关键遗漏全部被发现，越权修改为 0；
- §9 现有未决项都有 ID、风险路由、截止点和证据要求；
- 首个真实纵切完成一次有效挑战、一次无效挑战拦截和一次证据复现；
- goals / AGENTS / README / architecture-outline / roadmap / ai-native-engine / check-docs 投影一致；
- 达成后转“已验证”；首个纵切复核后才转“已冻结”。冻结的是权限、记录和采用边界，
  决策面、风险阈值、检查表和提示词继续按 §10 演化。

## 13. 明确不做

- 宣称能够保证发现所有未知的未知；本协议保证的是主动暴露、追踪和从逃逸中学习。
- 让多个模型投票替代证据，或让同一上下文自写、自审、自宣通过。
- 因为所有者未发现问题，就把沉默视为批准。
- 允许 AI 自行修改不变量、hard oracle、权限、历史记录或自身采用门槛。
- 让高风险未知冻结整个项目；只暂停依赖它的不可逆提交。
- 为了“流程完善”无限增加字段、会议、agent 或文档，而不测漏判与审阅负担。

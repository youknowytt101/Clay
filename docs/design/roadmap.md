# 开发计划 · 从零到闸门 F

> **对应 goals.md v18。本文是 §6 路线的施工版**——把阶段拆成可交付的包，标出依赖、体量、
> 验收、砍单顺序，以及每个未决项的决策截止点。
>
> **不含工期**（goals.md §0.5 第 1 条）。体量用相对档位：
> **S** 一两天量级 · **M** 一周量级 · **L** 数周量级 · **XL** 一个月以上量级。
> 这些是**相对大小**，不是承诺。
>
> **顺序的总原则**：先自用 → 再验证 → 再开放。

---

## 零 · 关键路径

```
 ADR-002 求值语义 ──────────────────┐
 （纸面，不依赖任何工具链）         │
                                    ▼
 打包器 ──► ECS 内核 ──► Action 层 ──► 事件表运行时 ──► RTS 模板
            └─► Rapier spike           │                 │
                （不过就换库）          ├─► 寻路 · 视野    │
                                        ├─► 选择指令建造  │
                                        └─► 皮肤包 · 视听 ┘
                                                          │
                          AI 作者接口 ◄────────────────────┤
                          （describe · 约束层 · 适配层）    │
                                                          ▼
                                              动画栈档 2 ──► 第三人称动作模板
                                                                   │
                                                                   ▼
                                                              闸门 F
```

**三条硬依赖，谁都绕不开：**

| # | 依赖 | 后果 |
|---|---|---|
| 1 | **求值语义 → 一切** | Action 层、序列化、试飞台断言全部受它约束。定错了迁移链救不回来 |
| 2 | **打包器 → ECS / Rapier / glTF** | 没有构建步骤，这三件事第一天就撞墙 |
| 3 | **Rapier 确定性 → 决策 29 整条线** | 不过就换物理库。**必须在闸门 A 之前验，不是最后验** |

**唯一可以完全并行的**：ADR-002 是纸面工作，不依赖打包器，**现在就能做**。

| M1-d **试飞台** | M | M1-b M1-c | headless runner：加载 → 执行 Action 序列 → 断言 → 报告 |

| M1-g **分块与流式加载** | L | M1-c M1-f | S1–S3 三条纪律；**这是 M1 最大的一块** |

**验收 · 闸门 A**（三条）+ **闸门 B**（纸面：城市迁移演练）

**砍单顺序**：gizmo / 多选 → 空间索引的 BVH（先只做网格哈希）→ **绝不砍试飞台**

**先做 M1-e**。它是唯一可能推翻已定决策的一项，越早发现越便宜。
**M1-i 别推后**：接一次最小 AI，验的是「Action 层的形状对不对」，晚发现贵一个数量级。

## M2 · 事件表与 RTS 模板（体量 XL+，全程最大的一段）

**这一段有掉进无正反馈黑洞的真实风险**（风险 3——原来的解药「发链接给别人」已随分发链推后）。
**所以它内部切成四个各自有产出的小段**，每段结束时手里有个能动的东西。

### M2-1 · 第一个能玩的东西（体量 M）

| 包 | 体量 | 内容 |
|---|---|---|
| 事件表数据模型 + 逐行求值 | M | 按 M0-a 冻结的语义实现 |
| 列表编辑器 | M | 拖拽、加规则行、挑条件动作、改参数、分组 |
| 第一批条件动作（最小集） | S | 碰到 / 输入意图 / 定时；移动 / 生成 / 销毁 / 改属性 |
| 物理接入 + 平台跳跃脚手架 | M | **不作交付模板**，是最快的可玩闭环 |

> **产出：一个能跳、能踩到平台、能通关的东西。** 这是整个项目第一次「玩到自己做的东西」。

### M2-2 · 逻辑是数据的证明（体量 L）

| 包 | 体量 | 内容 |
|---|---|---|
| **§4.7 五个概念的数据模型定死** | M | 场景流程 · 行为单元 schema · 可持久化声明 · 数据表 · 动态集合 |
| 五个概念的最小实现 | M | 两场景切换 · 一个带参行为单元 · 存读进度 · 一张数据表被引用 · 一个背包能增删并存档 |
| 行为单元 + 配方库 | M | 展开即普通规则行 |
| 约束层机制 | M | 谓词注册 + 结构化失败反馈 + 面板显示 |
| **A1 / A2 留口** | S | Action 日志的 checkpoint 字段；`apply()` 返回带「本步改了什么」 |

> **数据模型定死是这一段的核心交付**，实现可以薄。定错了撞 I11。

| 包 | 体量 | 内容 |

| 包 | 体量 | 内容 |
|---|---|---|
| 皮肤包机制 + 编辑面板 + 两套皮肤 | M | |
| 视听下限一套 | L | 音频 · 预制粒子 · 材质与光照预设 · 后处理档位 |
| 游戏内 UI overlay + 预制件 | M | |
| 导出自包含工程文件 | S | 本轮的终点 |
| 教程系统机制 + 已交付能力的条目 | M | 决策 35 的载体 |
| **RTS 模板本身** | XL | **这是内容生产，不是引擎开发——见下** |

**验收 · 闸门 C**（五条）

**砍单顺序**：视野迷雾的精细化（先做最粗的圆形视野）→ 内置素材库规模 → 后处理与部分预制粒子 → **绝不砍导出，也绝不砍寻路与确定性**

**M2 的最大陷阱**：M2-4 的「RTS 模板」是关卡设计 + 数值平衡 + 美术，**和写引擎是两种工作**。
它很可能比 M2-1 到 M2-3 加起来还耗时间（风险 11）。**砍范围时优先砍内容的量，不砍引擎能力。**

**砍单顺序**：界面页数量（先做标题 + 结算）→ 关卡数量（先做 1 关跑通全流程）→ **绝不砍动画栈档 2**——它是这一段的全部意义

**M3.5-b 必须在 M3.5-a 之后、M3.5-e 之前**。root motion 的两条冲突解法没落地就开始做模板，
等于把泄漏写进内容里，返工要改已经做好的动作。

## 一 · 决策截止点

**每个未决项都有一个「再不定就要返工」的时刻。** 按里程碑排：

| 里程碑 | 必须定的 |
|---|---|
| **M0 之前** | 事件表求值语义（已前置，ADR-002） |
| **M1 内** | ECS 库选型（spike）· 组件 schema 定义方式 · 块的大小与加载策略 · **Rapier 跨平台确定性** |
| **M2-2 之前** | 场景切换的状态语义 · 可持久化声明粒度 · 数据表引用语法与作用域 · 动态集合持久化粒度 · 内容包最小字段集 |
| **M2-3 内** | 寻路实现选型 · 视野迷雾粒度 · 输入意图第一批清单 · 条件动作由谁实现 |
| **M2-4 内** | 数值表达力够不够（**真写一遍伤害公式**）· 1000 实体可达性实测 · 视听资源来源 · 依赖与素材许可 · 配方与教程条目清单 · 视觉插槽粒度 |
| **M3 内** | 能力探测怎么做 · 降级重试预算 · 内置 AI 成本谁承担 · AI 输出的安全边界 · 最小度量 |
| **M3.5 之前** | 动画状态机的数据形态 · root motion 烘焙时机 · 界面页实现形态 |
| **M4 之前** | 后端最小形态 · 快照体积上限 · OAuth 选型 |

## 二 · 两类工作要分开排

| | 引擎开发 | 内容生产 |
|---|---|---|
| 是什么 | 内核、编辑器、AI 层 | 模板关卡、皮肤、配方、教程条目、素材库 |
| 特点 | 后补要重构 | **后补只是排期** |
| 出现在 | M1、M2-1~3、M3、M3.5-a/b | M2-4、M3.5-e，以及每个能力的教程条目 |
| 砍的时候 | **最后砍** | **先砍量**（一套皮肤而不是两套、3 个配方而不是 8 个） |

**风险 11 的执行点就在这张表**：M2-4 和 M3.5-e 加起来可能比全部引擎工作还大。
**它们的进度要单独跟踪，不要和引擎进度混在一个数字里。**

## 三 · 每个里程碑的「第一件事」

| 里程碑 | 先做这个 | 为什么 |
|---|---|---|
| M0 | 求值语义定稿 | 唯一不可逆，且零成本 |
| M1 | **Rapier 确定性 spike** | 唯一可能推翻已定决策的一项 |
| M2 | 平台跳跃脚手架 | 最快拿到「玩到自己做的东西」，对抗风险 3 |
| M3 | 供应商适配层 | 它决定其余部分能不能在弱模型上跑通 |
| M3.5 | **§4.4 的两条 root motion 冲突解法** | 不先落地就会把泄漏写进内容 |

## 四 · 什么时候该停下来重估

| 信号 | 动作 |
|---|---|
| Rapier 确定性 spike 不过 | 换物理库。**不放宽决策 29** |
| ECS 库 spike 的确定性测试不过 | 换库或自研（预算上限 3 周，adr-001 §6） |
| 1000 实体在 M2-4 实测不达标 | 先优化；仍不达标才考虑模拟细节分级（现为留口） |
| RTS 模板的逻辑写不出来、必须硬编码 JS | **加受限原语，不退回节点图**（§7.2） |
| 闸门 D.5 教程可用性连续两轮不过 | 走退役条件 **P-2**：重估决策 12 的取消 |
| 闸门 F 通过后开放阶段迟迟无法开工 | 走退役条件 **P-1**：承认它是个人引擎，资源转回引擎能力 |

**闸门不过怎么办：砍范围，不放宽判据。** 一旦允许「先放过，下阶段补」，闸门就退化成装饰。

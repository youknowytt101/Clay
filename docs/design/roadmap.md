# 开发计划 · 从零到闸门 F

> **对应 goals.md v23。本文是 §6 路线的施工版**——把阶段拆成可交付的包，标出依赖、体量、
> 验收、砍单顺序，以及每个未决项的决策截止点。
>
> **不含工期**（goals.md §0.5 第 1 条）。体量用相对档位：
> **S < M < L < XL**，**只表示相对大小，不折算成天数**（goals.md §0.5 第 1 条）。
> 唯一允许出现的时间是**技术止损时间盒**（如「Rapier spike 最多 3 天」），它是实验的退出条件。
>
> **顺序的总原则**：先自用 → 再验证 → 再开放。

```
 ADR-004 决策治理 ┈┈┈┈┈┈┈┈┈┈┈┈┈► 所有 AI 指挥任务 / ADR / 实现（横切约束，非时序前置）

 ADR-002 求值语义 ───────────────► 事件表运行时 ──► RTS 模板 ─────────────┐

            └─► Rapier spike          ▲               │                  │
                （不过就换库）         │               ▼                  │
 ADR-003 控制协议 ────────────────────┘       PlanContract / orchestrator   │
 （纸面；事务字段落地前走通）                         │                    │

                                                    │                    ▼
                                                    └────► 动画栈档 2 ──► 第三人称动作模板 ──► 闸门 F
```

**五条硬依赖，谁都绕不开：**

| # | 依赖 | 后果 |
|---|---|---|
| 1 | **求值语义 → 一切** | Action 层、序列化、试飞台断言全部受它约束。定错了迁移链救不回来 |
| 2 | **打包器 → ECS / Rapier / glTF** | 没有构建步骤，这三件事第一天就撞墙 |
| 3 | **Rapier 确定性 → 决策 29 整条线** | 不过就换物理库。**必须在闸门 A 之前验，不是最后验** |
| 4 | **控制协议 → Action 事务 / TestSpec / M3 编排** | `baseRevision`、步骤原子性、hard oracle 与证据字段若到 M3 才定，会反向重写 M1 / M2 |
| 5 | **决策治理 → 所有 AI 指挥工作** | 没有 `TaskContract`、决策面、挑战和证据采用边界，AI 会把用户没发现的空白静默补成架构。**G0 前 AI 不得自行宣布不可逆结论生效**——但可以推演、可以提交候选，批准权在项目所有者。**这不构成对 M0-a 的时序前置** |

**三份 ADR 都是纸面工作，不依赖打包器，因此可以并行推进。**
**ADR-002 排第一**——它是全项目唯一「定错了没有退路」的一项，也是唯一能改变项目状态的动作。
ADR-004 的 G1/G2 与它**并行**，不排在它前面：G0 约束的是 **AI 越权宣布结论**，不是禁止推演；
而 ADR-002 的冻结本来就要由项目所有者按闸门 O 批准（[ADR-004](adr-004-evidence-governed-evolution.md) §3 的 L1 层）。
ADR-003 只需在 M1 的 Action 事务格式落地前走通。

## 二 · 两类工作要分开排

| | 引擎开发 | 内容生产 |
|---|---|---|
| 是什么 | 内核、编辑器、AI 层 | 模板关卡、皮肤、配方、教程条目、素材库 |
| 特点 | 后补要重构 | **后补只是排期** |
| 出现在 | M1、M2-1~3、M3、M3.5-a/b | M2-4、M3.5-e，以及每个能力的教程条目 |
| 砍的时候 | **最后砍** | **先砍量**（一套皮肤而不是两套、3 个配方而不是 8 个） |

**风险 11 的执行点就在这张表**：M2-4 和 M3.5-e 加起来可能比全部引擎工作还大。
**它们的进度要单独跟踪，不要和引擎进度混在一个数字里。**

| M0 | **求值语义（M0-a）；治理 G1/G2 并行** | 唯一不可逆的一项排第一。治理并行防 AI 静默补义，但不前置——它已经推迟 M0-a 四个版本了 |
| M1 | **Rapier 确定性 spike** | 唯一可能推翻已定决策的一项 |
| M2 | 平台跳跃脚手架 | 最快拿到「玩到自己做的东西」，对抗风险 3 |
| M3 | 供应商适配层 | 它决定其余部分能不能在弱模型上跑通 |
| M3.5 | **§4.4 的两条 root motion 冲突解法** | 不先落地就会把泄漏写进内容 |

## 四 · 什么时候该停下来重估

| 信号 | 动作 |
|---|---|
| Rapier 确定性 spike 不过 | 换物理库。**不放宽决策 29** |
| ECS 库 spike 的确定性测试不过 | 换库或自研（预算上限 3 周，adr-001 §6） |
| 1000 实体在 M2-4 实测不达标 | 先优化；仍不达标才考虑模拟细节分级（现为留口） |
| RTS 模板的逻辑写不出来、必须硬编码 JS | **加受限原语，不退回节点图**（§7.2） |
| 闸门 D.5 教程可用性连续两轮不过 | 走退役条件 **P-2**：重估决策 12 的取消 |
| 闸门 F 通过后开放阶段迟迟无法开工 | 走退役条件 **P-1**：承认它是个人引擎，资源转回引擎能力 |
| 新证据反驳当前方案，或出现未登记的高风险假设 | 发 `DecisionChallenge`；只暂停相关不可逆提交，用 challenger 影子验证，不静默改 champion |

**闸门不过怎么办：砍范围，不放宽判据。** 一旦允许「先放过，下阶段补」，闸门就退化成装饰。

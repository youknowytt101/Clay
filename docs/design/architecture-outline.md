## 一 · 它是什么

> **一个 AI 与人共用同一条编辑通道的通用 3D 网页游戏引擎编辑器：
> 游戏逻辑是数据，AI 和鼠标是同一个命令层的两个前端，产出的是同一种材料。**

| | |
|---|---|
| **形态** | 网页优先的编辑器 + 播放器，同一个应用切播放模式；播放期与编辑器**分包** |
| **面向** | 有经验的游戏研发人员。门槛由**内置 AI + 内置教程**承担，不靠削能力 |
| **维度** | 只做 3D（2D 用正交相机应付） |
| **逻辑层** | **事件表**（有序的「当……就……」规则行）+ 行为单元 + 数据表。没有节点图、没有画布 |
| **实体模型** | ECS，对用户可见（术语不做翻译） |
| **本轮终点** | 导出自包含工程文件。分享链接、账号、后端在**开放阶段**，不在本轮 |

**三条不可让步**：

| | |
|---|---|
| **I1** | 编辑期一切变更只经由 Action 层 |
| **I3** | AI 的产出与人手做的是同一种材料 |
| **I2** | 游戏逻辑是数据，可读、可逐行 diff、可被约束层校验（**I1 的前提**） |

> 溯源：goals.md §0.1、§0.2、§2

### 契合度的一般规律

**覆盖面由「节奏 + 相机 + 移动是不是玩法本身」决定：**

| 轴 | 类型 | 判断 |
|---|---|---|
| **强项** | RTS、MOBA、塔防、战棋、roguelite、经营、ARPG、解谜 | 俯视 / 秒级 / 指令驱动。架构每一处选择都在帮忙 |
| **中等** | 魂类 Boss 房、塞尔达神庙、平台跳跃、TPS、复古 FPS | 第三人称 / 房间尺度 / 帧级战斗 |
| **弱项** | 跑酷动作、格斗、体育 | **移动或出招本身即产品**。动画栈封顶在档 2 |
| **本轮不做** | 竞技 FPS、MMO（**封顶**，§十一）；体素生存（**留口**，§十） | — |

### 三道闸

任何玩法能不能做，先过这三道：

| 闸 | 边界 | 挡掉什么 |
|---|---|---|
| **动画闸** | 档 2：状态机 + 混合 + root motion。**无 IK、无动作匹配、无上下半身分层** | 跑酷、格斗、体育 |
| **规模闸** | 同屏完整模拟实体 **1000**，无 LOD / impostor，桌面 60fps | 千级弹幕、城市人群、体素世界 |
| **网络闸** | 本轮无联机；方向已定为 **lockstep**，服务器权威路线封顶 | 竞技对抗、MMO |

## 四 · 内核能力清单

**这是「能力如何」的正面回答。** 每项写清做到哪儿。

### 4.1 世界与状态

| 能力 | 做到哪儿 |
|---|---|
| 实体 / 组件表 / 原型查询 | 完整 |
| 组件 schema 注册 | 字段范围、枚举、实体引用、单位、说明——支撑详情面板自动生成与 AI 可读 |
| 系统注册与调度 | 固定步长 + 帧步长两条 |
| 序列化 | 确定性、版本化信封 + 迁移链、可 diff、**按块存取** |
| 快照与回滚 | 全世界快照；播放沙箱靠它 |
| **分块与流式加载** | 场景内分块、实体随块加载卸载。**不做** LOD 层级、impostor、地形简化 |

**分块的三条纪律**：加载顺序不得影响模拟结果；玩法需要的最小状态常驻（只有表现随块进出）；卸载重载后同输入同结果。

### 4.2 变更（Action 层）

| 能力 | 做到哪儿 |
|---|---|
| Action Registry | id / JSON Schema 参数 / 前置条件 / 影响域 / 可逆性 / describe |
| 撤销栈 + 变更日志 | 内存栈 + 存档时落盘。**不做**事件溯源存储 |
| `listAvailableActions(context)` | 情境级自省：此刻能做什么、影响谁、能不能撤销 |
| params schema 约束 | 必须是可直接喂给模型做约束解码的 JSON Schema 子集 |

### 4.3 逻辑

| 能力 | 做到哪儿 |
|---|---|
| **事件表** | 条件 / 动作 / 分组 / 变量 / 等待 / 重复 / **多层子事件** / **参数位算术** |
| 求值语义 | 全表自上而下 + 触发即时插入；实体集按种类收窄、子事件只继承不回写、顶层规则之间不传递（**冻结，见 adr-002**） |
| **行为单元** | 带参数、有 schema 的可复用规则组。展开即普通规则行。**不允许递归与任意控制流** |
| **配方** | 行为单元的预设 = 单元 + 默认参数 + 一句说明 |
| 条件动作的实现 | JS 是正常路径，但**跑在确定性沙箱里**：禁 `Date` / `Math.random` / 网络 / 存储，由内核注入 `rng` 与 `tick`，注册时静态检查 |
| **封顶** | 任意控制流、递归、完整表达式语言 |

### 4.4 数据与流程

| 能力 | 做到哪儿 |
|---|---|
| **场景与流程** | 多场景（各自可编辑可试玩）+ 流程数据（顺序与切换条件）+ 全局状态 / 场景内状态分界 |
| 界面页 | 标题 / 暂停 / 背包 / 对话 / 结算，DOM overlay 实现，是流程里的节点 |
| **数据表** | 具名表 + 有 schema 的列 + 按行 id 取值。行 id 只增不改。**不做**公式列、外部表格同步 |
| **运行期动态集合** | 有序集合 + 键值表；加入 / 移除 / 取值 / 计数；元素限标量与实体引用；插入序稳定。**不做**排序、过滤、嵌套查询 |
| **运行期存档** | `存进度(槽位)` / `读进度(槽位)`；游戏自己声明存什么；等待队列也在存档范围内。**不做**云存档、多槽管理界面 |

### 4.5 空间与物理

| 能力 | 做到哪儿 |
|---|---|
| Transform 层级 | 是组件，不是场景图 |
| 空间索引 | 网格哈希 / BVH |
| 拾取 | 射线拾取、框选（编辑期） |
| 刚体与碰撞 | Rapier：刚体 + 碰撞 + 空间查询 |
| **关节** | **固定 + 铰链**，配「连接 / 断开」两个事件表动作。**不做**马达、布娃娃、软体 |
| **群体寻路** | 群体寻路 + 局部避让，确定性。查询接口与实现分离 |
| **视野与战争迷雾** | 按阵营视野计算 + 迷雾状态 + 「X 是否可见」查询。**迷雾是玩法状态，参与断言** |

### 4.6 玩法能力（播放期）

| 能力 | 做到哪儿 |
|---|---|
| **选择与指令** | 点选、框选、编队、对选中集下指令（移动 / 攻击 / 跟随 / 停止） |
| **放置与建造** | 位置合法性校验、消耗资源、放置预览、可撤销 |
| **技能目标选择** | 点地 / 点单位 / 方向 / 范围指示器，是行为单元的参数形态 |
| **输入意图** | 事件表只认意图（跳跃 / 确认 / 移动），设备绑定是一张可换的映射表 |

### 4.7 呈现

| 能力 | 做到哪儿 |
|---|---|
| **kind 注册表** | 声明碰撞体、占地尺寸、可用动画状态、**动画状态的位移曲线** |
| **皮肤包** | `kind → 模型 / 材质 / 缩放 / 动画状态映射 / 图标`。一个工程一个当前皮肤，可覆盖到单实体。编辑器内可创建与编辑 |
| **动画（档 2）** | glTF clip + 交叉淡化 + **状态机** + **混合** + **root motion** + **动画事件**（clip 时间点）。**封顶：IK、动作匹配、上下半身分层** |
| 相机 | 四档（受限俯视 / 肩后跟随 / 第一人称 / 自由飞行）+ 平滑 + 震动 + 锁定目标 |
| 音频 | 音效 / BGM / 音量 / 循环 / 停止，全是事件表动作。**不做**空间音频、混音 |
| 特效 | 预制粒子（命中 / 爆炸 / 拾取 / 尘土 / 拖尾）。**不做**粒子编辑器 |
| 材质与光照 | 参数面板 + 环境与光照预设。**不做**节点式材质编辑器、烘焙 |
| 后处理 | 预设档位（关 / 柔和 / 强烈）。**不做**自定义链 |
| 游戏内 UI | DOM overlay + 实体锚点 + 预制件（血条 / 计分 / 计时 / 提示 / 胜负）。**不做**控件系统 |

**呈现与玩法的分界线**（换皮不得改变玩法）：

| 归玩法（kind / 逻辑） | 归呈现（皮肤包） |
|---|---|
| 碰撞体、占地尺寸 | 模型、材质、缩放 |
| **root motion 位移曲线** | clip 本身、混合权重、过渡时长 |
| **动画状态机的当前状态与转移** | 状态映射到哪个 clip |
| 迷雾的可见性状态 | 迷雾怎么画 |

### 4.8 AI 基础设施

| 能力 | 做到哪儿 |
|---|---|
| **三个入口** | `describe(scope, detail)` / `listAvailableActions(context)` / `apply(actions[])`。**不做**一个 Action 一个 tool |
| `describe` | 语义 LOD，可寻址可下钻，**返回结构化数据不返回文案** |
| **约束层** | 谓词 + 结构化失败反馈四元组（`at` / `observed` / `limit` / `alternatives`） |
| 供应商适配层 | OpenAI 兼容端点 + Anthropic / Gemini 原生 + 本地模型。**能力探测 + 自动降级** |
| **不做** | 模型路由、RAG、微调、多模型投票、**引入通用 agent 框架作依赖**（不等于禁止自主循环） |

**AI 介入形态**（按实现顺序）：单步指令 → 换皮 → 多步变更集 → 生成规则行 → 内联建议。

**AI 参与度分三档**（决策 40）：

| 档 | 能力 | 状态 |
|---|---|---|
| **1** | 上述五种形态 + **AI 在 headless 里自己试玩并报告** | **本轮做** |
| **2** | **受监督的自主循环**：跑一步 → 读约束反馈 → 决定下一步；进度可见、随时叫停、可回滚到 checkpoint、可只接受前半段 | **留口** |
| **3** | **AI 造零件**：用 JS 实现新的条件与动作。**不得自动注册**——必须过沙箱静态检查 + headless 断言，registry 标明来源 | **留口** |

**封顶的是形态不是规模**：产出必须始终是 Action 序列。任务多大都行，
不可寻址、不可手改的黑盒结果不行。

**档 1–2 的能力天花板**：**AI 能组装，不能造零件**。超出现有条件动作库的需求，得由人先写零件。

### 4.9 平台与工程

| 能力 | 做到哪儿 |
|---|---|
| **宿主能力抽象** | 全屏、指针锁定、URL、存储、文件读写各一层薄接口 |
| **播放期分包** | 播放期不依赖任何编辑器 UI。**这条不允许放宽** |
| 数据安全 | 自动保存；导出自包含工程文件；overlay 一律 `textContent`；导入设上限并优雅失败 |
| **试飞台** | headless runner（加载 → 执行 Action 序列 → 断言 → 报告）+ 确定性 |
| **教程系统** | 按能力组织、可交互、就在编辑器里。**每个概念一条，跟着能力一起交付** |

> 溯源：goals.md §5.1、§3.4、§4.4、§4.7、ai-native-engine.md

## 五 · 数据模型

**一个工程里有什么，怎么套起来：**

```
工程
├─ 流程                    哪个场景先来、什么条件切下一个
├─ 全局状态                跨场景保留
├─ 场景[]
│   └─ 块[]                加载卸载的单位
│       └─ 实体[]          = kind + 组件数据
├─ 事件表                  规则行[]（有序）
│   ├─ 条件行[] 动作行[]
│   ├─ 子事件（多层）
│   └─ 行为单元定义[]      带参数 schema；配方 = 它 + 默认参数
├─ 数据表[]                作者编辑，静态，行 id 只增不改
├─ 运行期集合声明[]        有序集合 / 键值表
├─ kind 注册[]             碰撞体 / 占地 / 动画状态 / 位移曲线
├─ 当前皮肤包              kind → 视觉
├─ 输入绑定表              意图 → 设备
└─ 依赖的内容包[]          包 id + 版本
```

**三种「状态固化」**：

| | 工程存档 | 导出工程文件 | 运行时存档 |
|---|---|---|---|
| 存什么 | 编辑期世界状态 + 流程 + 事件表 | 工程的自包含固化 | 游戏声明的持久化状态 |
| 权威 | Action 层 | 导出那一刻的工程 | 事件表运行时 |
| 带版本 | 是 | 是 | 是 |

**内容包**——模板 / 皮肤 / 配方 / 数据表 / 素材集 / 模块**是同一种东西**：

```
内容包 = { 稳定 id, 语义化版本, 作者, 许可, 依赖(包 id + 版本), 内容哈希, 载荷 }
```

**五处「可替换的东西都是一张映射表」**：`kind → 视觉`、`动画语义状态 → clip`、`输入意图 → 设备`、`包 id + 版本 → 内容`、`Action 标签 → 能力面视图`。

> 溯源：goals.md §4.5、§4.7、§3.5

## 六 · 运行期：一帧发生什么

**玩法跑在固定步长的 tick 上；呈现跑在帧上。两者分离。**

```
── 固定步长 tick（玩法，确定性范围） ──────────────────
  1. 采样输入意图，冻结本 tick 的输入快照
  2. 物理步进（Rapier）
  3. 排空触发队列（FIFO，深度上限 16，超限 warning 不崩）
  4. 全表自上而下求值常规规则
  5. 结算等待队列
──────────────────────────────────────────────────

── 渲染帧（呈现，只读消费） ────────────────────────
  渲染桥增量同步 → 动画状态机求值 → 粒子 / 音频 / 后处理
  块的加载与卸载（呈现层事件，不是玩法事件）
──────────────────────────────────────────────────
```

**确定性的范围**：所有「逐字节一致」的断言**限定在玩法状态**，不含渲染与视听状态。

**保住它的四条**：实体迭代按稳定 id 升序；随机数只来自内核注入的带种子 rng；JS 条件动作跑在沙箱里；触发在 tick 边界对齐、不在物理子步内回调。

**编辑期 vs 播放期**：

| | 编辑期 | 播放期 |
|---|---|---|
| 权威 | Action 层 | 事件表运行时 / 系统 |
| 直接写状态 | 否 | 是 |
| 撤销栈 | 有 | 无 |
| 约束校验 | 实时 | 不校验 |
| AI 可介入 | 是 | 否 |

进入播放 = 打快照，退出 = 整体回滚。**播放期改动不污染工程。**

> 溯源：adr-002、goals.md §4.5、§7.1

## 七 · 编辑器界面

**一套能力面，没有模式切换，没有术语翻译。**

| 面板 | 改什么 |
|---|---|
| 模板库 | 打开即见，选一个先直接试玩 |

| **数据表编辑器** | 按列 schema 生成的表格视图 |
| **动画状态机编辑器** | 状态 + 转移条件的列表视图；转移条件复用事件表的条件注册表 |
| 皮肤切换 | 一个下拉换整套风格；缺插槽当场列出 |

## 八 · 领域模块与模板

**模块 = 组件 + 系统 + 条件动作 + kinds + 皮肤包 + Action + 约束 + 面板 + 模板**，一个声明文件，启动时校验。

| 模板 | 覆盖 | 模块内容 |
|---|---|---|
| **RTS / MOBA** | 红警、星际、魔兽、Dota、**塔防** | 单位群、波次与 AI、建筑与生产、资源、胜负、迷雾呈现 |
| **第三人称动作** | 塞尔达、艾尔登、刺客信条、TPS | 角色控制器、战斗与判定、锁定、背包与装备、关卡流程 |

**平台跳跃**是内部脚手架（最快拿到可玩闭环），不作交付模板。

**模块禁止**：import 别的模块内部实现、读写不属于自己的组件表、绕过 Action 层、import 第三方 ECS 库、在事件表或玩法组件里引用具体美术资源、在条件动作实现里触碰时间与随机源。

> 溯源：goals.md §5.6、§7.1

## 九 · 硬性指标

| 指标 | 值 |
|---|---|
| 播放期首包（不含用户素材） | ≤ 8 MB gzip |
| 桌面冷启动到可玩 | ≤ 5 秒 |
| 目标帧率 | 桌面 60fps |
| 同屏**完整模拟**实体 | **1000** 不掉帧 |
| 单块加载耗时 | ≤ 1 帧预算 |
| 场景总量 | 不设上限（按块加载） |

**三条永远成立的约束**：

| | |
|---|---|
| **确定性** | 逐帧严格确定性，硬要求，不允许降级 |
| **标识符稳定（I11）** | `kind` / 条件动作 / 配方 / 皮肤插槽 / 数据表行 id / 内容包 id **一旦发布即冻结**；要改就新增 + 标 deprecated + 保留迁移 |
| **求值语义冻结** | 事件表的求值语义定稿后按 I11 对待。**全项目唯一「定错了没有退路」的地方** |

> 溯源：goals.md §3.6.1、§3.6.2、adr-002

## 十一 · 方向性封顶（要做就得先推翻决策）

| 封顶 | 后果 |
|---|---|
| **动画档 3**：IK / 动作匹配 / 上下半身分层 | 跑酷、格斗、体育做不了；刺客信条只到潜入 + 战斗 |
| **竞技 FPS 路线**：服务器权威 + 客户端预测 + 反作弊 | CS / Valorant 类做不了 |
| 图灵完备的事件表：任意控制流、递归 | 需要任意算法的玩法要下沉成 JS 条件动作 |
| 2D 一等公民（Sprite 管线） | 2D 只能用正交相机 + billboard 应付 |
| 节点图作控制流 / 画布 / 连线 | — |
| 引擎内 3D UI 控件系统 | 游戏内 UI 只有 DOM overlay |
| 节点式材质编辑器、烘焙管线 | 材质只到参数 + 预设 |
| 自研物理 / 自研文生 3D / 自研音频引擎 | 全部集成或接 provider |
| 编排逻辑用代码（而非数据） | 破 I1 与 I3，AI 通道直接失效 |
| **产出不可寻址、不可手改的黑盒结果** | AI 的任务规模不封顶，产出形态封顶——必须是 Action 序列 |
| 能力面的数据分叉 | 任何裁剪视图必须是 registry 的视图 |
| 用用户的 key 做用户没要求的事 | — |
| 道路系统新功能 | 存量冻结 |

# 编辑器 UI 约定

> 目的只有一个：**让前端迭代不产生风格漂移。**
> 本文是约定（写代码时要遵守的规则），不是设计方案——不讨论「界面该长什么样」，
> 只规定「颜色、间距、字号从哪来，什么不许写」。

---

## 1. 先分清两个视觉域（最容易搞错的一条）

| | 编辑器 UI | 游戏内呈现 |
|---|---|---|
| 是什么 | 面板、工具栏、大纲、详情、对话框、事件表 | 玩家看到的一切：模型、材质、光照、特效、血条与计分 |
| 谁定义 | **本文的令牌** | **皮肤包**（goals.md 决策 20） |
| 换风格意味着 | 换编辑器主题（亮 / 暗） | 换游戏美术风格 |
| 允许用户改吗 | 否（只有主题切换） | **是，这是产品能力** |

**两者不共享令牌，不共享组件，不互相引用。**

最常见的错误是把**游戏内 UI 预制件**（血条、计分、胜负画面）当成编辑器组件来做。
它们是游戏的一部分，跟着皮肤包走——编辑器改主题不该让谁的血条变色。
这是不变量 I9 在样式层的延伸。

---

## 2. 令牌是唯一来源

**所有颜色、间距、字号、圆角、动效时长，只能来自 CSS 自定义属性。**

现有令牌（继承自 GameHub，语义命名，**保持不变**）：

| 组 | 令牌 |
|---|---|
| 表面 | `--surface-window` `--surface-panel` `--surface-header` `--surface-well` `--surface-ctrl` `--surface-hover` `--surface-active` `--surface-popover` |
| 线条 | `--border` `--groove` `--line-width` `--selection-width` |
| 文字 | `--text-strong` `--text-secondary` `--text-muted` `--text-dim` |
| 强调 | `--accent` `--accent-hover` |
| 间距 | `--space-1`…`--space-7`（2 / 4 / 6 / 8 / 12 / 16 / 24px） |
| 字号 | `--font-micro` `--font-control` `--font-section` `--font-base`（10 / 11 / 12 / 13px） |
| 圆角 | `--radius-sm` `--radius-md` `--radius-lg`（2 / 3 / 4px） |
| 控件 | `--strip-h` `--icon-btn` `--icon-size` `--pad-x` `--indent` `--label-col` |
| 动效 | `--transition-fast` |

**命名规则：按用途命名，不按外观命名。**
写 `--surface-panel` 不写 `--gray-24`；换主题时前者仍然成立，后者会变成谎言。

### 待补的缺口（迁移时第一批要做的）

现状扫描：`:root` 之外有 **30+ 处硬编码色值**，其中大多数是**状态色没有令牌**。必须补上：

```
--state-danger        危险 / 禁建 / 删除        （现被硬编码为 #c42b1c #e88a8a #6b3535）
--state-warning       警告 / 需要注意           （现被硬编码为 #e8b87a）
--state-success       成功 / 校验通过
--state-info          提示
```

每个状态色需要**三档**：文字、边框、底（弱背景）。约束层的提示、AI 的变更预览、
皮肤包完整性的缺口标记，全部要用它们——**不补齐，这三处会各自造一套颜色**。

---

## 3. 三条禁止

| 禁止 | 为什么 |
|---|---|
| **组件里写死颜色值** | 漂移的头号来源。已有 30+ 处，迁移时清零 |
| **组件里写死像素间距 / 字号** | 只能用 `--space-*` `--font-*`。需要新档位就加令牌，不要就地写 |
| **组件私有令牌** | `--ol-*` 这类。**布局尺寸**（列宽、缩进）可以局部，**颜色与字号绝对不行** |

判定标准很简单：**这个值换主题时该不该变？** 该变 → 必须是令牌。

---

## 4. 双模式靠令牌表达，不靠第二套样式

goals.md 决策 12 的 M1 要求两种模式共享同一份实现。落到样式上：

> **简易 / 专业模式的差异只能通过令牌值与元素显隐表达，不得出现第二套组件 CSS。**

密度差异（专业模式更紧凑）由一组令牌覆盖实现：

```css
:root[data-density="pro"] { --strip-h: 24px; --space-4: 6px; --font-base: 12px; }
```

**出现 `.panel--simple` 这样的类名，就是 M1 已经被破了的信号。**

---

## 5. 一条设计原则（唯一一条）

> **编辑器要安静。唯一有颜色的东西是内容。**

界面用中性灰阶，强调色只用于选中、焦点与状态；3D 视口、素材缩略图、用户自己的作品
是画面里唯一的彩色区域。理由是决策 19——目标用户是美术，**工具抢戏会直接影响他们对自己作品的判断**。
Blender 与 Figma 都遵守这一条。

---

## 6. 图标与文案

- **图标**：**Lucide 是唯一来源**，ISC 授权的浏览器包固定在 `vendor/lucide/`，
  编辑器渲染控件时不需要联网。
  静态插入 `<i data-lucide="name" aria-hidden="true"></i>`；
  JS 插入用 `window.AppIcons.markup('name')` 后调 `window.AppIcons.refresh()`。
  **先找现成的 Lucide 图标，再考虑自绘。** 纯图标按钮必须有本地化的 `title` 与 `aria-label`；
  尺寸由外层组件决定，渲染器统一用 `currentColor`、圆角端点、`1.7` 描边。
  动效只用来传达状态或反馈，要尊重 `prefers-reduced-motion`，且不能替代无障碍标签。
  升级 Lucide 时，`lucide.min.js` 与 `LICENSE` 必须来自同一个官方 npm release，并记录固定版本
- **文案**：术语一律走 goals.md §0.3 的术语对照表，由 i18n 承载。
  **术语层就是防「文案漂移」的机制**，跟令牌防「视觉漂移」是同一件事
- **无障碍**：本轮只要两条低成本的——**所有控件键盘可达**、**文字对比度不低于 4.5:1**。
  图标按钮的 `title` / `aria-label` 要求见上一条。不做完整 WCAG 审计
- **安全**：游戏内 UI overlay 插入用户文案一律 `textContent`，**禁止 `innerHTML`**
  （goals.md §3.6.4，最现实的一处 XSS）

---

## 7. 防漂移的执行机制

文档也会漂移，所以要有一条能自动跑的检查（对齐 goals.md「判据必须可判定」）：

> **一个扫描脚本**：在 `:root` 之外发现硬编码色值、或 `--space-*` 之外的像素间距，即报错。
> 挂进 `tests/`，和其他离线测试一起跑。

允许豁免，但豁免要写在脚本的白名单里、附一行理由——**豁免必须是显式的**。

---

## 8. 暂不做

| 不做 | 理由 |
|---|---|
| 完整组件目录 / 组件库文档 | 三次法则。同一个组件形态出现第三次再抽象并写下来 |
| 多套编辑器主题 | 先做暗色一套。令牌命名已经保证了日后加亮色不用改组件 |
| 可视化令牌编辑器 | 用户改的是**游戏**风格（皮肤包），不是编辑器风格 |
| 设计稿工具里的镜像系统 | 单人项目，代码即唯一来源；再维护一份 Figma 变量只会两边不一致 |
